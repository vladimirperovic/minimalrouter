# Minimal Router OS v0.3.0

**Status:** Beta / controlled pilot

v0.3.0 reorganizes the dashboard's operational pages around authoritative router
state. LAN & DHCP, Firewall and Gateway Quality become unified workspaces; Logs,
Recovery and DNS Filter are redesigned so that hidden pages stop polling, stale
requests can no longer overwrite newer views, and asynchronous operations are
tracked through verified completion or failure instead of an HTTP 202.

Routing, NAT, PPPoE, WireGuard and DNS-filter enforcement keep their existing
privilege boundary: `routerd` remains the unprivileged management plane and every
privileged change still goes through `router-applyd` with the same
confirmation, rollback and signed-update gates.

## Upgrading

v0.3.0 changes tools that run outside the A/B slot. The shared configuration
store migrates named snapshots, durable recovery and backup-export metadata and
sanitized transaction audit records, which changes `router-recovery` and
`router-setup`; Go 1.26.9 with updated `x/net`, `x/crypto` and `x/sys` (October
2026 vulnerability fixes) also changes the bootstrap build inputs.

Existing v0.2.1 and earlier appliances therefore take v0.3.0 through the signed
full distribution installer once. The dashboard's **New version** button
correctly refuses this transition; its byte-identity and rollback checks are
unchanged. New installations use the v0.3.0 Golden ISO. A replacement appliance
can be installed from the Golden ISO and given the old router's configuration
through an encrypted backup restore. See [`WEB-UPDATE.md`](../WEB-UPDATE.md).

Configuration admission is stricter in a few places. Validation rejects a LAN
address that is the network, broadcast, loopback or multicast address, requires
explicit upstream DNS resolvers even when DHCP allocation is disabled (dnsmasq
remains the LAN resolver), and requires a custom rule's source CIDR to lie
entirely inside the LAN. Restores and the configuration store apply the same
rules, so check a backup with a restore preview before relying on it.

## Highlights

### LAN & DHCP

- One address map and device/reservation inventory replace the separate lease
  and reservation editors. Shared forms protect against concurrent edits, keep
  drafts across refreshes and show explicit lease freshness.
- Known DHCP collisions (a new gateway address or reservation that is currently
  leased to another device) are rejected before apply for the dashboard, MCP
  and restores alike. Observations can reject a collision but never claim that
  an address is free.
- Gateway address changes keep confirmation/rollback and link to the candidate
  management address.

### Firewall

- Presets have stable ownership, report modified matches, preserve manually
  named rules and can be reviewed and applied as one batch. New presets restrict
  LAN-to-WAN traffic; existing all-network denies keep their scope.
- Configured policy is shown separately from sampled base-chain and loaded
  revision observations, with generation-scoped per-rule counters and a
  read-only connection-policy explanation. Unknown routes and dynamic schedules
  are never presented as verified access.
- Change previews describe firewall and network differences before apply, and
  recent firewall transaction outcomes are kept in the audit log.

### Gateway Quality

- Unavailable or stale measurements are distinguished from disabled monitoring.
  Manual checks, per-target results, time-based charts and bounded outage and
  recovery histories are available; during a detected outage the link is
  sampled at least every 30 seconds while the existing auto-recovery freshness
  and safety gates stay in force.

### Logs, Recovery and DNS Filter

- Logs: server-side audit filters and cursor pagination over retained history,
  startup summaries with selected-boot samples, structured disk usage and
  CPU/RAM charts.
- Recovery: named manual snapshots with 20-per-kind retention, snapshot
  previews, and backup, pfSense and snapshot restores bound to the reviewed
  configuration revision. Restore and DNS continuation are persisted; DNS
  policy is restored only after the network change is confirmed. Backup export
  timestamps are retained independently of audit pruning.
- DNS Filter: applied-protection overview, searchable profiles and exceptions,
  DHCP device selection, minute-precise schedules, offline edits using verified
  installed catalogs and a persisted history of the last 20 operations. Status
  probes no longer hold the global network apply lock.

### MCP

Read-only MCP tools gain firewall observations, four LAN tools, recovery and
startup diagnostics, DNS domain explanation, profile context and operation
history. Each tool documents the limits of its evidence; legacy mutation
handlers that are not advertised are rejected even in admin mode.

## Validation

All required workflows passed on the release candidate's production code,
including Linux Go race tests, vet and vulnerability scanning, ARM64/QEMU smoke
tests, the network namespace laboratory, crash/fuzz/benchmark checks, a clean
Alpine installation, four dashboard browser profiles and the Golden ISO
blank-disk flash, reboot and firstboot E2E. The signed release workflow repeats
the ISO installation against the exact tagged release. No physical-router
validation is claimed by this note.
