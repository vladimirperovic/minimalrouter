# Minimal Router OS v0.4.0

**Status:** Beta / controlled pilot

The router runtime is now Rust. New Golden installations use Alpine 3.24 with
the Linux 6.18 LTS kernel and the fix for **CVE-2026-98432**. The dashboard
remains React/TypeScript. Default WAN isolation, the unprivileged `routerd` /
privileged `router-applyd` boundary, signed firmware, confirmation and rollback
remain part of the appliance contract.

## What changed

- All router executables, recovery/setup/update tools, firmware signing tools
  and the optional MCP bridge build from `rust/` as static AMD64/ARM64 binaries.
  v0.3.3 is the last Go release; its implementation remains in Git history.
- New images use Alpine 3.24.3 and the 6.18 `linux-lts` series. The build rejects
  kernels below 6.18.56, unknown series and mismatched kernel/module releases.
  It checks both the live installer kernel and the Golden installed kernel.
  The full installation test checks the kernel actually booted from disk.
- Unused kernel modules are pruned only after dependency checks; required
  networking modules must remain available. Initramfs is rebuilt from that same
  module tree in CI. The live installer still only verifies and raw-copies the
  Golden image.
- Configuration timestamps remain identical across privileged application,
  commit and reload. This also covers changes requiring confirmation.
- Monotonic time readings prevent wall-clock jumps from extending rate-limit
  windows and other elapsed-time calculations. Oversized `Expect: 100-continue`
  bodies are rejected before the client is invited to send them.

The Linux CVE fix is documented in the
[official CVE record](https://www.cve.org/CVERecord?id=CVE-2026-98432).
The exact kernels used by each ISO are recorded in `/minimalrouter/BUILD-INFO`;
the installed build records `/etc/minimalrouter/kernel-release`.

## Upgrading

**Every appliance running v0.3.3 or earlier needs the full signed distribution
installer once.** The Rust bootstrap tools differ from the Go tools, so the
dashboard updater correctly refuses that transition. Do not bypass its
signature, architecture, anti-downgrade or runtime-layout checks.

The application installer preserves the existing Alpine branch and does not
upgrade its kernel. Installing v0.4.0 application files alone therefore does
not fix a vulnerable kernel on an existing appliance.

- To get the complete new OS, install the Golden ISO on a blank replacement
  disk/VM, complete firstboot, restore an encrypted configuration backup and
  verify the replacement before switching production links. Existing disks are
  deliberately refused by the flasher.
- To retain Alpine 3.22, use its official kernel security update separately and
  reboot. The fix starts at 6.12.113 in the 6.12 line. Confirm `uname -r`, not
  just the installed APK package version.

See the [installation guide](https://github.com/vladimirperovic/minimalrouter/blob/v0.4.0/docs/INSTALLATION.md#upgrading-to-v040)
and [update compatibility](https://github.com/vladimirperovic/minimalrouter/blob/v0.4.0/docs/WEB-UPDATE.md).

## Validation and limits

Release publication requires CI, CodeQL, Secret scan, Deep validation,
Performance, Service supervision, Appliance ISO and the complete installed
QEMU Lab on the exact candidate. The Signed release workflow then builds from
signed distributions and repeats full blank-disk installation, reboot,
firstboot, serial/SSH login, networking, service readiness and installer-safety
checks before attaching assets and publishing.

Rust validation includes frozen comparisons with Go v0.3.3: 502 configurations,
1,401 generated service files, 500 signed manifests and 2,000 version comparisons.
An additional 3,000 named API request contracts run through HTTPS locally and
against the installed QEMU appliance, alongside network, recovery and chaos
scenarios. These are request contracts, not 3,000 independent features. The
suite is not a one-for-one port of the Go tests and has no Go race detector.

This remains Beta software. Synthetic QEMU results do not prove a particular
ISP, physical NIC, installed UEFI boot or unattended long-term operation. The
[validation record](https://github.com/vladimirperovic/minimalrouter/blob/v0.4.0/docs/CURRENT_VALIDATION.md)
separates those limits from the automated evidence.
