# Minimal Router OS v0.4.1

**Status:** Controlled-pilot Beta. Publication requires the exact-commit release gates.

This patch verifies the supplied Rust audit and fixes confirmation, resource
handling and persistence issues in the shared router core. The detailed
[review](https://github.com/vladimirperovic/minimalrouter/blob/v0.4.1/docs/SECURITY-REVIEW-0.4.1.md) distinguishes confirmed defects from
intentional trade-offs and additional hardening.

## Changes

- Changed WireGuard clients retire the old peer session and require a new
  post-activation handshake, even with
  keepalive disabled. Both processes use the same freshness/future-time rules.
- Trusted networks reject overly broad public ranges and masked unspecified
  networks while preserving existing ULA and normal CIDR host-bit semantics.
- applyd returns connection capacity after handler panic and rejects oversized
  IPC frames rather than silently truncating them.
- HTTP sockets have a 30-second write inactivity timeout. Ambiguous request
  framing, overflowing Content-Length and invalid header names are refused;
  VT content sniffing is corrected.
- DNS risk classification releases the feed publication lock before SQL queries.
  DNS filtering reuses bounded catalog connections, reaps finished workers and
  records panics as unconfirmed outcomes requiring review.
- Persistent bearer session identifiers are hashed; legacy plaintext sessions
  are revoked. Backup and MCP-owned secret buffers use erasure guards.
- TLS files are created private, update-channel preferences are synced, archive
  extraction validates the root before writing and uses bounded permissions,
  and revision arithmetic refuses overflow.

- SSH accepts `root` only. Alpine's `openssh-server` has no PAM, and on musl
  an unpatched `sshd` accepted any 257–1024 byte password for an account whose
  shadow field is `*` ([Alpine advisory](https://alpinelinux.org/posts/2026-11-05-openssh-password-authentication-bypass/),
  OpenSSH 10.6p2). Root always has a real password hash, so `AllowUsers root`
  leaves the bypass no account to reach. The Golden rootfs build also refuses
  an `openssh-server` older than Alpine's fixed `10.3_p1-r2`.

- Four production-parser fuzz targets now run with AddressSanitizer in CI,
  with daily longer campaigns and weekly corpus pruning. The isolated QEMU
  Lab also runs weekly. Targeted mutation tests verify WG/IPC regression quality. See [FUZZING.md](https://github.com/vladimirperovic/minimalrouter/blob/v0.4.1/docs/FUZZING.md).

## Upgrading

Appliances at or below v0.4.0 need the full signed distribution installer once:
shared validation/storage changes also affect bootstrap tools outside the A/B
slot. Preserve signature, architecture, version-floor and runtime-layout checks.
A complete replacement OS comes from a Golden ISO on a blank disk/VM followed by
firstboot and encrypted configuration restore. The live ISO still only verifies
and raw-copies its image; existing disks remain protected against overwrite.

The full installer adds `AllowUsers root` to an already provisioned appliance's
`sshd_config` unless the operator set AllowUsers/AllowGroups; it takes effect
after the reboot that completes the installation. Other Linux accounts can no
longer log in over SSH. Neither installer nor web update replaces Alpine
packages, so an existing appliance keeps its `openssh-server` until the operator
runs `apk add -U --upgrade openssh-server` and `rc-service sshd restart` from
the root console. Upgrade only that package: a full `apk upgrade -a` would also
replace the kernel that the Golden image validated together with its initramfs
and modules.

Before upgrading, narrow any trusted ranges the new validation rejects. Expect
a fresh login after migration. When changing an idle WireGuard client without
keepalive, generate tunnel traffic and confirm only after a new handshake;
otherwise let the normal confirmation timeout roll back the change.

## Validation

See [CURRENT_VALIDATION.md](https://github.com/vladimirperovic/minimalrouter/blob/v0.4.1/docs/CURRENT_VALIDATION.md) for collected evidence.
Windows tests and Linux cross-compilation do not establish installed appliance
behavior. CI, CodeQL, Secret scan, Deep validation, Performance, Service
supervision, Appliance ISO and the complete QEMU Lab must pass on the exact
candidate. The signed release then repeats full installation with the signed
payload before publication. No real ISP, physical NIC, power-cut or unattended
production validation is claimed.
