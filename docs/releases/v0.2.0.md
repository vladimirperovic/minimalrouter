# Minimal Router OS v0.2.0

**Status:** Beta / release candidate; publication requires the release gates.

v0.2.0 adds network-wide DNS risk alerts for adult, phishing, malware, fraud and
gambling domains. New phones, tablets, consoles and changing MAC/IP addresses
do not require an inventory for these alerts to work.

## Using it

Open **DNS Activity** and enable recording. Five maintained Block List Project
lists download automatically and matching stays on the router. Recording was
already enabled in v0.1.9? The risk monitor starts automatically after upgrade.
Allow time for downloads; missing lists and collection failures are visible.

The dashboard shows new alerts in the bell, sidebar and page summaries. Review
the domain, category, time, request count and last observed IP; mark a daily
alert reviewed or create a removable domain/category notification exception.
All-alert history remains available with category filters and pagination.

This is a DNS lookup signal, not proof of a visit, viewed content, infection or
blocking. Background apps/adverts can trigger it. External encrypted DNS, VPNs
and mobile data can bypass it. No automatic category blocking or email/push
delivery is added in this version.

## Privacy and storage

Matched list domains and last observed IPs are retained locally for the DNS
retention period, with a 10,000-alert bound. They can include full listed
hostnames. Raw individual lookup entries remain in RAM. **Delete history** and
disabling recording delete alerts; saved notification exceptions and public
list caches remain. No observed domains are uploaded to the list provider.
See [Privacy](../../PRIVACY.md) and [DNS risk guide](../DNS_RISK_ALERTS.md).

The public-source check on 2026-10-08 produced about 110 MiB of active disk
indexes. Two generations are retained; memory caches remain bounded. Failed
updates keep the previous validated list and critical storage pressure stops
nonessential writes. List data is not shipped in the firmware.

## Dashboard corrections

DNS collection state now comes from successful collection, with failures and
gaps visible. Device choices remain available after filtering, search is
debounced, and clearing history cannot repopulate it from queued work.
WAN, DHCP, Wi-Fi, proxy and DynDNS labels now distinguish configuration from
measured runtime evidence. Every sidebar page was reviewed; see the
[review and follow-up priorities](../DASHBOARD_REVIEW_v0.2.0.md).

## Upgrade and evidence

Deterministic local builds of `router-update`, `router-recovery` and
`router-setup` are byte-identical to v0.1.9 on amd64 and arm64. The normal signed
dashboard update path is preserved for v0.1.8/v0.1.9; v0.1.7 and older still
need the one-time signed full installer described in the v0.1.8 notes.
Golden installation, firmware verification and rollback rules are unchanged.

Using the release's Go 1.25.13 toolchain, all six bootstrap hashes also match
the actual published v0.1.9 manifests. All 12 installed integration files match
the published AMD64 payload. An unmodified v0.1.9 installation therefore needs
no bootstrap or system-file migration for this candidate. Final signed release
verification and the device's normal staging/preflight checks still apply.

The exact release candidate must pass all seven workflows, including the full
Appliance ISO install/boot checks, before tagging. Local code/browser/source
checks are recorded in [current validation](../CURRENT_VALIDATION.md); they are
not real-appliance or ISP validation. This remains a controlled-pilot Beta.
