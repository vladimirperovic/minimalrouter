# Minimal Router OS v0.1.9

**Status:** Beta / controlled pilot

v0.1.9 adds opt-in DNS activity statistics: which sites each device looks up,
over time, with sites from the device-profile categories such as Adult
highlighted. The MCP bridge gains read-only tools so an AI client can read that
history, the audit log, firewall activity, traffic insights and health.

Routing, NAT, DHCP, firewall and WireGuard behaviour are unchanged. DNS
resolution is unchanged unless DNS activity recording is switched on.

## Upgrading

v0.1.9 does not change the tools that run outside the A/B slot
(`router-update`, `router-recovery`, `router-setup`): they build byte-identical
to v0.1.8. A v0.1.8 appliance takes v0.1.9 from the dashboard's **New version**
button. v0.1.7 and older appliances still need the signed full distribution
installer once, as described in the [v0.1.8 notes](v0.1.8.md).

New installations use the v0.1.9 Golden ISO.

## Highlights

### DNS activity (Operate → DNS Activity)

Recording is **off by default**. When switched on:

- `router-applyd` installs one fixed dnsmasq drop-in,
  `/etc/dnsmasq.d/minimalrouter-dns-activity.conf`, which logs queries to
  `/run/minimalrouter-dns-queries.log` on tmpfs, and restarts dnsmasq. If
  dnsmasq rejects the drop-in or does not come back, the drop-in is removed and
  dnsmasq restarted without it, so DNS never depends on statistics.
- The helper drains and truncates that log every minute and passes only
  validated client addresses, query names and counts to `routerd` over a
  dedicated socket.
- `routerd` stores daily lookup counts per device and registrable site, plus
  hourly totals per device, writing once every five minutes. Full hostnames
  are kept only in an in-memory list of the most recent 2,000 lookups.
- History is kept for up to 90 days (30 by default), bounded per day and in
  total, skipped under critical disk pressure, and deleted when recording is
  turned off or with **Delete history**. Setting changes and deletions are
  audited.

The page shows lookups over time, the most active devices, categorized sites
per device, a filterable site table and the recent lookups. Lookups that bypass
the router's resolver — encrypted DNS in the browser, VPNs, mobile data — are
not seen. DNS activity is browsing history; see [`PRIVACY.md`](../../PRIVACY.md).

The setting is kept in `routerd`'s local store rather than in the canonical
configuration, so it is not part of configuration backups and the release stays
web-updatable.

### Read-only MCP insight tools

`get_dns_activity`, `get_recent_dns_lookups`, `get_security_events`,
`get_firewall_activity`, `get_traffic_insights` and `get_health` join the
existing read-only tools. Read-only sessions may now read the metadata-only
audit log; every mutation from them is still rejected. See
[`docs/MCP.md`](../MCP.md).

### Dependency maintenance

Dashboard build tooling overrides move `brace-expansion` to 5.0.11 or later and
`source-map-js` to 1.2.2 or later for new high-severity advisories. The shipped
dashboard bundle is unaffected.

## Evidence and limits

See [`CURRENT_VALIDATION.md`](../CURRENT_VALIDATION.md). CI runs every required
workflow including the blank-disk Golden ISO install and the namespace network
laboratory. DNS activity recording has not yet been exercised on a real
appliance. It remains a controlled-pilot Beta, not an unattended
pfSense/OpenWrt replacement.
