# Minimal Router OS v0.2.1

**Status:** Beta / controlled pilot

v0.2.1 fixes DNS category-blocking activation with real-size catalogs. On v0.2.0
every activation rolled back ("DNS filter activation failed; previous DNS
configuration restored") because the resolver generation probe fired exactly
once into the post-restart gap: OpenRC reports the restart complete as soon as
the new process forks, while dnsmasq with several hundred thousand records
needs longer to serve, so the lone UDP probe was lost. The probe is now
retried until a bounded deadline, and the failing activation stage is logged
on the appliance for diagnosis.

Routing, NAT, DHCP, firewall, WireGuard, DNS activity and risk-alert behaviour
are unchanged.

## Upgrading

v0.2.1 does not change the tools that run outside the A/B slot
(`router-update`, `router-recovery`, `router-setup`): they build byte-identical
to v0.1.8. A v0.1.9 or v0.2.0 appliance takes v0.2.1 from the dashboard's
**New version** button. Older appliances still need the signed full
distribution installer once, as described in the [v0.1.8 notes](v0.1.8.md).

New installations use the v0.2.1 Golden ISO.

## Highlights

### Reliable filter activation

Category blocking (Operate → DNS → Network protection) now survives the
resolver restart with production catalogs. No policy or list changes are needed:
check categories and apply again after the update.

### Apply placement and refresh guidance

The Network protection card carries its own **Apply protection** action next to
the status, so categories apply without scrolling past the domain checker and
exceptions. The maintained-lists panel explains why **Refresh lists** is
unavailable (nothing applied yet, or unapplied changes pending) instead of
leaving a dead button; lists for newly checked categories still download
automatically on apply.
