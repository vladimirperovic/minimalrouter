# Minimal Router OS v0.3.2

**Status:** Beta / controlled pilot

v0.3.2 fixes what a live test of the published v0.3.1 ISO and of the
full-installer upgrade from v0.3.0 found. The test was a Hyper-V installation with
a simulated PPPoE ISP and a LAN client.

It also closes a DNS filtering gap found on a production appliance. Safari
Private Browsing on macOS resolved a domain that the adult category blocks
through Apple's Oblivious DNS-over-HTTPS. The router answered NXDOMAIN, but the
lookup never reached it.

The privilege boundary is unchanged: `routerd` remains the unprivileged
management plane and every privileged change goes through `router-applyd` with
the same confirmation, rollback and signed-update gates.

## Upgrading

`router-update`, `router-recovery` and `router-setup` are byte-identical to
v0.3.1 on AMD64 and ARM64. The installed integration files are unchanged.

- **v0.3.1 appliances** take v0.3.2 as an ordinary signed dashboard update
  (**Updates → New version**), with the usual A/B rollback.
- **v0.3.0 and earlier appliances** need the signed full distribution installer
  once.

See [`WEB-UPDATE.md`](../WEB-UPDATE.md).

After the update, the DNS Filter page reports **Force all devices through router
DNS** as partly enforced if it was on before. Apply it again to add the new
DNS-over-QUIC rule.

## Added

- **Encrypted DNS, VPN & proxy bypass** is a fifth DNS filter category, backed
  by HaGeZi DoH/VPN/TOR/Proxy Bypass. It is off by default.
- When enabled, router DNS returns NXDOMAIN for:
  - known DNS-over-HTTPS/TLS/QUIC resolvers;
  - iCloud Private Relay ingress (`mask.icloud.com`, `mask-h2.icloud.com`),
    which Apple documents as the way a network turns Private Relay off;
  - VPN, Tor and proxy services.
- The category also blocks commercial VPN apps and Tailscale.
- Hard-coded resolver IP addresses, unlisted endpoints, self-hosted VPNs and
  mobile data still bypass DNS filtering.

## Fixed

### DNS enforcement

- **Force all devices through router DNS** blocked DNS-over-TLS on TCP 853 but
  not DNS-over-QUIC on UDP 853. The preset now blocks both.

### Dashboard access

- Sign-in was refused when the disk was 90 % full or more, which hid the page
  reporting the full disk. Sign-in now stays available. Only a completely full
  disk, where no session can be stored, still refuses it.
- WireGuard clients reached the dashboard page, but every request was refused,
  because the default trusted networks cover only the LAN.
  - While WireGuard is on, the Security page now says so and offers **Trust
    WireGuard network**.
  - WireGuard-only management is refused unless the tunnel network is trusted.
- Confirmation dialogs open in the centre again.

### Installation and diagnostics

- After the full signed installer, `/etc/minimalrouter/VERSION` still named the
  replaced release.
- DNS Activity alerts said "checks failed" while the category lists were still
  downloading after the feature was switched on.

## Deferred

These v0.3.1 live-test findings change files outside the A/B slot, so they wait
for a release that needs the full installer anyway:

- firstboot accepts a very short recovery/SSH root password;
- the audit log is ordered by wall-clock time;
- a killed service supervisor leaves orphans that an OpenRC restart cannot clear.

## Validation

All required workflows passed on the merged changes. They include:

- Linux Go race tests, vet and vulnerability scanning;
- ARM64/QEMU smoke tests;
- the network namespace laboratory;
- a clean Alpine installation;
- four dashboard browser profiles;
- the Golden ISO blank-disk flash, reboot and firstboot E2E.

`scripts/ci/bootstrap-compatibility.sh` against v0.3.1 reports
`WEB_UPDATE_SUPPORTED=true`. The signed release workflow repeats the ISO
installation against the exact tagged release.

Not validated:

- No lab or physical-hardware run of v0.3.2 has been made.
- Whether the new category makes Safari Private Browsing fall back to router DNS
  has not yet been confirmed on a real device.
