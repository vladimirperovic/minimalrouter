# Minimal Router OS v0.3.1

**Status:** Beta / controlled pilot

v0.3.1 fixes what a live test of the published v0.3.0 ISO found: a Hyper-V
installation with a simulated PPPoE ISP and a LAN client, driven through the
installer, firstboot, the dashboard and the API. The two serious ones stopped
installations on common hardware and rolled back ordinary configuration changes
whenever the DNS filter categories were on. The release also makes direct DNS
enforcement a visible switch, and tightens the dashboard on narrow screens.

The privilege boundary is unchanged: `routerd` remains the unprivileged
management plane and every privileged change goes through `router-applyd` with
the same confirmation, rollback and signed-update gates.

## Upgrading

v0.3.1 changes `router-recovery` and `router-setup`, which run outside the A/B
slot. The snapshot-ordering and restore-preview fixes live in the shared
configuration store, and the LAN address check reads the ARP table through the
shared network package; both are compiled into those two tools. `router-update`
is byte-identical to v0.3.0.

Existing v0.3.0 and earlier appliances therefore take v0.3.1 through the signed
full distribution installer once. The dashboard's **New version** button
correctly refuses this transition; its byte-identity and rollback checks are
unchanged. New installations use the v0.3.1 Golden ISO, which carries the
driver, boot-prompt and module fixes below. A replacement appliance can be
installed from the Golden ISO and given the old router's configuration through
an encrypted backup restore. See [`WEB-UPDATE.md`](../WEB-UPDATE.md).

## Fixed

### Installation

- Installed appliances only brought up VirtIO network cards. Hyper-V, emulated
  Intel e1000 and physical Intel/Realtek ports stayed invisible, and firstboot
  stopped with "at least two usable network interfaces are required". The
  image now loads drivers for the hardware it finds (`mdev` and `hwdrivers` in
  the sysinit runlevel) and runs the stock shutdown services, so a reboot
  remounts the root filesystem read-only. The ISO end-to-end test now uses an
  e1000 LAN port so this stays proven.
- The serial installer entry could not be selected on BIOS boots. A five-second
  `boot:` prompt appears on VGA and the serial console (Tab lists the entries);
  the default still starts on its own, at the latest after 30 seconds.
- The live ISO mounts its own module image and no longer prints `/lib/modules`
  errors.

### Configuration and DNS

- With the DNS filter categories enabled (about 510,000 domains), every WAN,
  upstream-DNS or device-profile change, including pausing a profile, was
  rolled back with "connection refused": the post-apply DNS check ran before
  dnsmasq had loaded its lists. `router-applyd` now waits up to 15 seconds for
  the resolver to answer.
- The LAN address check treats devices the router has recently seen on the LAN
  as conflicts, even without a DHCP lease.
- A backup restore preview no longer reports a phantom isolated-segment change.

### Gateway Quality and history

- Internet outages are recorded while PPPoE stays connected, and each outage
  shows whether the link or the Internet was down.
- After the router clock was corrected, samples and snapshots stamped "in the
  future" were shown as the newest. History reads are bounded to the present,
  and snapshots are listed and pruned by configuration revision.

### Dashboard and release

- The dashboard no longer requests the configuration before sign-in.
- Release archives get a build-provenance attestation, so
  `gh attestation verify` works as documented.

## Changed

- The DNS Filter page leads with **Force all devices through router DNS**. It
  blocks direct DNS and DNS-over-TLS to other resolvers, so categories and
  device schedules cannot be skipped with a manually configured DNS server.
  Device profiles saved while schedules are off show an **Activate device
  schedules** button.
- Confirmations open in an in-page dialog instead of the browser's native box,
  which some embedded browsers dismissed automatically.
- Narrow screens: page headers wrap instead of squeezing the title; Traffic,
  DNS Activity, Security events and the Logs audit table show one card per row
  instead of a squeezed or sideways-scrolling table; the Logs startup timeline
  reads top to bottom; Overview status chips and topbar controls share one
  height, and the phone menu button sits in the topbar row.
- Wide screens: side-by-side cards end on the same line, LAN device actions
  stay on one line, and Firewall suggestions, WireGuard peers and QoS settings
  use the width available.

## Validation

All required workflows passed on the merged changes, including Linux Go race
tests, vet and vulnerability scanning, ARM64/QEMU smoke tests, the network
namespace laboratory, crash/fuzz/benchmark checks, a clean Alpine installation,
four dashboard browser profiles and the Golden ISO blank-disk flash, reboot and
firstboot E2E with an e1000 LAN port. The fixes were also exercised on the
Hyper-V lab with an ISO built from the fix branch; Hyper-V is not a qualified
platform, and that is not physical-router validation. The signed release
workflow repeats the ISO installation against the exact tagged release.
