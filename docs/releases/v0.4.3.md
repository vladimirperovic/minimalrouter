# Minimal Router OS v0.4.3

Beta candidate for controlled pilots with console recovery.

## Changes in v0.4.3

- A late confirmation can no longer cancel a network rollback. After an interrupted
  save, the router checks the active configuration before completing the change.
  Restoring a backup waits for the restored network before applying its DNS
  filtering policy. Recovery selects snapshots by revision across clock changes
  and keeps static leases that are usable on the recovered LAN.
- Turning DNS recording off clears stored lookups, alerts, queued checks and
  buffered resolver queries. Interrupted cleanup resumes after restart and
  finishes before recording can be enabled again.
- Turning device accounting off resets its history and counters. An idle counter
  is no longer counted again when an old month expires. Gateway latency, jitter
  and loss summaries weight each measurement equally across hourly groups.
- The updater can resume an interrupted signed release after rechecking the
  staged files. Retrying a request preserves newer pending work. The dashboard
  rejects stale confirmations and reports success after the target build is
  serving HTTPS. It distinguishes a verified rollback from an uncertain outcome
  that needs console verification.

This candidate also includes the unpublished v0.4.0 through v0.4.2 work. Pilot
users moving from v0.3.3 gain the Rust runtime, the Alpine 3.24 Golden image,
per-device DNS filter exemptions, Dynamic DNS drift reporting and the QoS
page speed test. See the [earlier changes](https://github.com/vladimirperovic/minimalrouter/blob/28c7af3d389516f7f91377d19ae2e96b9213d6cd/CHANGELOG.md).

## Upgrading

Appliances running v0.4.2 or earlier, including development installations, need
the **full signed distribution installer once**. The installed updater and
recovery tools live outside the A/B slots. For a complete OS replacement, use
the Golden image on a blank disk, finish firstboot and restore an encrypted
configuration backup. Keep the previous disk available until networking and
management access have been verified.

SSH from the LAN or WireGuard is now refused for sources outside
`trusted_networks`; an appliance whose `trusted_networks` holds no IPv4 network
has no SSH access until one is added. The `crond` and log-rotation job arrive
with the full installer or a new Golden image, not with an A/B web update; the
`sshd` limits and the recovery-password minimum apply to appliances installed or
first booted after this change.

The full installer adds `AllowUsers root` to an already provisioned appliance's
`sshd_config` unless the operator set AllowUsers/AllowGroups; it takes effect
after the reboot that completes the installation. Other Linux accounts can no
longer log in over SSH. Neither installer nor web update replaces Alpine
packages, so an existing appliance keeps its `openssh-server` until the operator
runs `apk add -U --upgrade openssh-server` and `rc-service sshd restart` from
the root console. Upgrade only that package: a full `apk upgrade -a` would also
replace the kernel that the Golden image validated together with its initramfs
and modules.

Before upgrading, narrow any trusted ranges the new validation rejects. Expect
a fresh login after migration. When changing an idle WireGuard client without
keepalive, generate tunnel traffic and confirm only after a new handshake;
otherwise let the normal confirmation timeout roll back the change.

## Validation

Local checks covered Windows and an isolated Alpine VM, signed firmware staging
and rollback using test keys, and desktop and mobile dashboard flows. A physical
router and a power cut during activation remain untested. The exact-commit CI,
full Lab and signed installation requirements are recorded in the
[validation record](https://github.com/vladimirperovic/minimalrouter/blob/main/docs/CURRENT_VALIDATION.md)
and [release process](https://github.com/vladimirperovic/minimalrouter/blob/main/docs/RELEASE_PROCESS.md).
