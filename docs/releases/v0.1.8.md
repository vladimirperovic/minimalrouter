# Minimal Router OS v0.1.8

**Status:** Beta / controlled pilot

v0.1.8 does three things. It gives the dashboard two complete themes and shows
what the router is actually carrying. It hardens authentication, the audit log
and uploads after a full review of the management plane. And it repairs
dashboard flows that a live end-to-end run found broken, including suggested
firewall rules that could never be switched on.

Routing, NAT, DHCP, DNS and WireGuard data-plane behaviour are unchanged. The
management plane changes where noted below.

## Upgrading from v0.1.7 — read this first

v0.1.8 changes the three tools that run outside the A/B slot and survive a
rollback: `router-update`, `router-recovery` and `router-setup`. The dashboard
updater therefore **refuses** v0.1.8 on a v0.1.7 appliance, by design. Install
it once with the signed full distribution installer from the local console or
an SSH session as root:

```sh
tar -xzf minimalrouter-linux-amd64.tar.gz
cd minimalrouter-linux-amd64
MINIMALROUTER_SKIP_CONSOLE_SETUP=1 sh install.sh
```

On a configured appliance the first-run console setup is skipped anyway;
the variable only suppresses its welcome screen.

The installer verifies the pinned signing key, the signed manifest,
architecture and file modes before it writes anything, refuses lower versions,
and keeps the configuration, DHCP leases and trust key. The A/B rollback
generation restarts with v0.1.8. If it is interrupted, the local console stays
available and the router services stay fenced until the installer is rerun.
Releases after v0.1.8 that keep these bytes are web-updatable again.

New installations use the v0.1.8 Golden ISO as before.

## Highlights

### Two themes and traffic insights

The dashboard ships **Noema** and **Studio**, each in light and dark. Traffic
insights show time history, the most active devices and a per-device
distribution; firewall activity counts allowed and blocked packets over a
bounded local window. The Overview's Active devices are derived from recent
routed traffic.

### Authentication and audit hardening

- A credential reset from the recovery console takes effect for every
  re-authentication prompt at once; before, password change, 2FA and backup
  kept accepting the revoked password until `routerd` restarted.
- A correct password with a wrong authenticator code no longer answers
  differently from a wrong password.
- Requests rejected before authentication are rate limited in the audit log,
  with suppression markers and counts, and can occupy only a bounded share of
  it, so a LAN client can no longer flush incident history.
- Offline firmware, backup and pfSense uploads get an extended read deadline
  after authentication instead of failing on slower links.

### Dashboard repairs

- Suggested firewall rules can be ticked and switched on; their checkboxes had
  zero width in both themes.
- A wrong current password is reported in place instead of signing the
  dashboard out.
- Backup restore and pfSense migration show their confirmation banner at once;
  the banner clears after an automatic rollback, and a refused confirmation
  states its reason.

### Other fixes

Manual snapshots are retained separately from automatic ones; the speed test
measures bounded time and works on slow lines; pfSense imports accept the
common `tcp/udp` forwards; encrypted backups from older releases restore again;
Wake-on-LAN requires a 48-bit address; WireGuard preshared keys resolve only a
unique peer. The complete list is in [`CHANGELOG.md`](../../CHANGELOG.md).

## Security note

A Windows helper script with an embedded account password was removed from the
repository root. It was unrelated to the router, but it had been published in
history; that account's password must be treated as exposed and changed.

## Evidence and limits

See [`CURRENT_VALIDATION.md`](../CURRENT_VALIDATION.md). CI ran every required
workflow including the blank-disk Golden ISO install and the namespace network
laboratory, and a local live suite exercised the dashboard against a real
`routerd` with simulated privileged operations. No new owner-Proxmox or ISP
evidence has been produced for v0.1.8. It remains a controlled-pilot Beta, not
an unattended pfSense/OpenWrt replacement.
