# Minimal Router OS v0.3.3

**Status:** Beta / controlled pilot

v0.3.3 closes a gap in the **Encrypted DNS, VPN & proxy bypass** DNS filter
category added in v0.3.2. On a production appliance running v0.3.2 with the
category on and DNS enforcement applied, an iPhone still opened a domain the
adult category blocks, in Safari Private Browsing.

The privilege boundary is unchanged: `routerd` remains the unprivileged
management plane and every privileged change goes through `router-applyd` with
the same confirmation, rollback and signed-update gates.

## Upgrading

`router-update`, `router-recovery` and `router-setup` are byte-identical to
v0.3.1 on AMD64 and ARM64. The installed integration files are unchanged.

- **v0.3.1 and v0.3.2 appliances** take v0.3.3 as an ordinary signed dashboard
  update (**Updates → New version**), with the usual A/B rollback.
- **v0.3.0 and earlier appliances** need the signed full distribution installer
  once.

See [`WEB-UPDATE.md`](../WEB-UPDATE.md).

The new names are added when a category list is downloaded. If the bypass
category is on, open **DNS Filter** after the update and use **Refresh lists**,
or wait for the next automatic refresh (within 24 hours). An Apple device
that already has a relay connection open keeps it until it reconnects, for
example after Wi-Fi or Airplane Mode is toggled.

## Fixed

- The router answered NXDOMAIN for `mask.icloud.com` and `mask-h2.icloud.com`.
  Both are CNAMEs, with a TTL of up to about 5.5 hours, to `mask.apple-dns.net`,
  whose TTL is 120 seconds. The upstream list does not contain that target.
  Apple devices that had cached the alias before the category was switched on
  kept resolving the target through the router, so Safari Private Browsing still
  reached Apple's relay for Oblivious DNS-over-HTTPS.
- The bypass category now always blocks:
  - `mask.icloud.com`, `mask-h2.icloud.com` and `mask.apple-dns.net`;
  - `mask-canary.icloud.com` and its alias `mask-canary.v.aaplimg.com`;
  - `use-application-dns.net`, Firefox's canary domain, which turns off
    Firefox's default-on DNS-over-HTTPS for the network.
- These names are maintained by the router and added to every valid download of
  the list. They count toward its entries and hash, and never make an empty or
  invalid download acceptable.

## Coverage check

The CNAME chains of about 2,000 resolver, relay and VPN names were resolved
publicly, and the router was asked for every hop. Google, Cloudflare (including
WARP), Quad9, NextDNS, AdGuard, OpenDNS, CleanBrowsing, Control D, Mullvad, the
Apple DoH names, Tor and the large commercial VPNs are blocked along the whole
chain. Small private DoH servers whose alias points at general hosting stay
open only for a device that cached the alias before the category was enabled.

Still not covered by name blocking:

- DNS-over-HTTPS sent straight to resolver IP addresses such as `1.1.1.1`,
  `8.8.8.8`, `9.9.9.9` and `94.140.14.14`;
- unlisted endpoints, self-hosted VPNs and mobile data.

On an iPhone or iPad you control, Screen Time **Limit Adult Websites** works on
every network and makes Safari Private Browsing unavailable.

## Deferred

Unchanged from v0.3.2. These findings change files outside the A/B slot, so they
wait for a release that needs the full installer anyway:

- firstboot accepts a very short recovery/SSH root password;
- the audit log is ordered by wall-clock time;
- a killed service supervisor leaves orphans that an OpenRC restart cannot clear.

## Validation

All required workflows passed on the merged changes. They include:

- Linux Go race tests, vet and vulnerability scanning;
- ARM64/QEMU smoke tests;
- the network namespace laboratory;
- a clean Alpine installation;
- four dashboard browser profiles;
- the Golden ISO blank-disk flash, reboot and firstboot E2E.

`scripts/ci/bootstrap-compatibility.sh` against v0.3.1 reports
`WEB_UPDATE_SUPPORTED=true`. The signed release workflow repeats the ISO
installation against the exact tagged release.

Not validated:

- No lab or physical-hardware run of v0.3.3 has been made.
- Whether Safari Private Browsing falls back to router DNS once the relay is
  unreachable has not yet been confirmed on a real device.
