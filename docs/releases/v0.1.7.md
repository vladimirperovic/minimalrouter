# Minimal Router OS v0.1.7

**Status:** Beta / controlled pilot

v0.1.7 does three things. It lets the appliance update itself from a published
release instead of from a shell. It reduces the dashboard to one appearance and
rebuilds the layer underneath it. And it repairs eleven findings from the
2026-09-05 technical review, two of which could lose a committed configuration
or accept a password that had already been revoked.

Routing, firewall, DHCP and WireGuard behaviour are unchanged. Update trust
behaviour **is** extended: the appliance can now be asked to install a signed
release from the dashboard.

## Highlights

### Updating from the dashboard

A **New version** button appears at the foot of the sidebar when a newer signed
release is published. Selecting it states what was found, what will happen and
what will not; the install runs behind a confirmation, writes into the inactive
A/B slot, and verifies the payload against that release's Ed25519 manifest
before anything is switched over.

An update is only offered when the release carries both the architecture's
archive and its signed manifest. A release missing either is not offered at
all, so the button cannot lead to a download that has nothing to verify it.

This required a change in how the appliance is built. `router-update` and
`router-recovery` embedded the commit hash and build time, so two builds of the
same source produced different bytes — and an A/B update could not establish
that it was installing the same bootstrap it was already running. Those two
binaries are now built without VCS stamping, and a CI job holds the property
against a recorded baseline so it cannot silently regress.

### One appearance

v0.1.6 shipped five appearances. v0.1.7 ships one: **Studio** — warm paper
ground, bronze accent, serif display type, measurements set large so a status
page reads like a printed sheet. The other four are removed, along with the
topbar control that selected them.

Carrying five looks is what produced a 16,000-line stylesheet for a page that
shows eleven numbers: 273 selectors declared in two or more base sheets, 112
`!important` declarations, and five different card paddings depending on which
sheet had last touched a section. Studio is now the design rather than an
option, and the layer underneath it is six small stylesheets — tokens, palette,
typography, surfaces, controls, Overview — each answering one question.

Two measured contrast failures are corrected. Section copy sat at 1.65:1
against the page ground, a third of the 4.5:1 that normal text requires, and
two steps below body size; the small-caps labels sat at 4.18:1. Both now clear
the line and the copy is at the body step.

Overview is recomposed. It was a card holding a card holding tiles, three
surfaces deep and all at the same weight, so nothing led. It is now one card
carrying one grid: the verdict, the three readings an operator checks next,
three groups of equal weight — Connection, Load, Trust & access — and the
appliance identity, all on the same columns.

The dashboard also stopped rewriting its own markup after rendering. A
presentation layer patched the DOM after React had drawn it, which races every
re-render; what it carried now lives in the components.

### The 2026-09-05 review

Eleven findings, repaired and covered by regression tests. In full in
[`CHANGELOG.md`](../../CHANGELOG.md); the two that could affect a running
appliance:

- **Recovery could revert a committed configuration.** When the canonical
  SQLite commit succeeded but the privileged helper's last-good acknowledgement
  failed, the engine kept the pre-transaction configuration in memory while the
  database and the running system held the new one. The recovery reconcile then
  rebuilt its request from the stale copy and pushed the previous settings back
  over a correctly applied revision.
- **A session could be issued against a revoked password.** A login that read
  the password hash, was preempted by a password change and then created its
  session picked up the *new* authentication generation — so a session proving
  only the old password passed validation. The hash and generation are now read
  as one snapshot, and the session row is inserted only while that generation
  is still current.

## Release signing

The SSH key that signed the v0.1.2–v0.1.6 tags was lost with the machine that
held it, and has been replaced. `MINIMALROUTER_RELEASE_ALLOWED_SIGNERS` now
contains only the new key, so **the v0.1.2–v0.1.6 tags no longer verify against
the current allowed-signers list.** Those releases remain published and their
artifacts remain signed by the firmware key, which is unchanged; it is the tag
signatures that can no longer be checked against the list. See
[`RELEASE_SECURITY.md`](../RELEASE_SECURITY.md).

The firmware signing key — the one an appliance uses to verify an update — was
not affected and has not been rotated. An appliance running v0.1.6 verifies
v0.1.7 with the key it already trusts.

## Validation

The exact release-candidate commit must pass all seven required workflows: CI,
CodeQL, Secret scan, Deep validation, Performance, Service supervision and
Appliance ISO.

v0.1.7 changes the Golden-image flasher's write verification, so the Golden ISO
gate is **re-run for this line** rather than inherited — twice, on each of the
two branches that alter what reaches the disk (see
[`CURRENT_VALIDATION.md`](../CURRENT_VALIDATION.md) for the exact runs). The
defect behind the change: `gzip -dc | dd`
reports only `dd`'s exit status, so a decompressor that failed after partial
output previously finished with "Golden image copied successfully" over a
truncated disk. Both stages are now checked and the written byte count is
compared against the uncompressed size recorded at build time.

Dashboard coverage includes the Playwright matrix across Chromium, WebKit,
mobile WebKit and mobile Chromium for both the production and demo builds. A
visual contract captures all fourteen sections at desktop and phone width plus
dark mode, the mobile drawer and both sign-in states. Its image comparison runs
where a baseline for the platform exists — only Windows baselines are
committed, so on the Linux CI runners the captures are skipped and the
rendering-independent assertions still run. CI does not currently check the
look; see the note in `web/e2e/theme-visual.spec.ts`.

## Scope and pilot status

v0.1.7 remains a **Beta / controlled pilot** release and inherits the v0.1.5
pilot conditions. Because routing, firewall, DHCP and WireGuard behaviour are
unchanged, an appliance already qualified on v0.1.6 does not need to repeat the
full network validation matrix.

Two things are new enough to warrant checking in the owner lab before relying
on them:

1. the dashboard reaches the appliance and reads correctly in the browsers
   actually used, since every page's presentation changed; and
2. an update installed from the dashboard completes, and the appliance comes
   back on the new slot.
